# Pipeline Contract

The application keeps runtime state outside project deliverables. Project folders contain only scientific artifacts.

| Order | Owner | Acceptance evidence |
| --- | --- | --- |
| 1 | Problem intake | normalized statement, data profile, valid subproblem DAG |
| 2 | Literature evidence | verified evidence map and deduplicated bibliography |
| 3 | Model design | implementable equations, method decisions, validation plan |
| 4 | Computational experiment | executed source, structured results, environment record |
| 5 | Result validation | baselines, diagnostics, robustness status |
| 6 | Scientific visualization | figure manifest, source data, scripts, publication exports |
| 7 | Paper authoring | compiled paper and claim-evidence manifest |
| 8 | Submission audit | independent PASS report and release manifest |

Critical failures stop progression. Warnings must be recorded but may proceed when they do not affect correctness or submission compliance.

This suite is an original synthesis. It adopts general ideas such as role separation, sequential handoff, reproducible computation, evidence-based writing, and independent verification. It does not copy external prompts, prose, templates, code, branding, or directory layouts. Scientific-figure and prose principles are re-expressed as competition-specific contracts rather than reproducing third-party skill text.
